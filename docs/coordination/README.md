# Координация AI-агентов

Эта папка — каноническое место для передачи работы между Claude Cloud, Gemini Local и Codex.
Git остаётся источником истины: сообщения в чатах полезны, но итог задачи должен быть виден в
ветке, commit и handoff-файле.

## Распределение ролей

- Claude и Gemini реализуют независимые задачи в отдельных ветках.
- Codex координирует порядок интеграции, проверяет diff, тесты, типы, сборку и риски.
- Владелец проекта принимает решения о функциональности и финальном merge в `main`.

## Жизненный цикл задачи

1. Создать ветку от актуального `main` или согласованной интеграционной ветки.
2. Записать краткую цель и границы задачи в PR или handoff-файле.
3. Реализовать задачу атомарными commits.
4. Запустить `npm run lint`, `npm test` и `npm run build` либо объяснить, почему проверка невозможна.
5. Отправить ветку в GitHub. Vercel создаст Preview Deployment для push/PR.
6. Передать ссылку на PR и Preview координатору.
7. После review исправить замечания в той же ветке.
8. Сначала интегрировать в `staging`/интеграционную ветку, проверить общий Preview, затем merge в `main`.

## Handoff-файл

Создавай файл `docs/coordination/handoffs/<имя-ветки>.md`. Имя должно быть уникальным для ветки.
Не редактируй handoff-файлы других агентов.

Минимальный шаблон:

```md
# Handoff: <название задачи>

- Агент: Claude | Gemini | Codex
- Ветка: `<ветка>`
- Commit: `<sha>`
- Статус: ready-for-review | changes-requested | blocked

## Сделано

- ...

## Изменённые области

- `path/to/file` — ...

## Проверки

- `npm run lint` — passed / failed / not run
- `npm test` — passed / failed / not run
- `npm run build` — passed / failed / not run

## Preview

- URL: <ссылка или `не создан`>

## Риски и продолжение

- ...
```

## Правила интеграции

- Не объединять две большие функциональные ветки вслепую.
- Сначала интегрировать изменения с меньшим количеством пересечений.
- После каждого merge повторять lint/test/build и проверять Preview.
- При конфликте не выбирать вариант автоматически: сначала понять намерение обеих веток.
- Production-секреты и production-базу данных не использовать в Preview без отдельного согласования.
