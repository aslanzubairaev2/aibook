## Сделано

1. **Синхронизация прогресса тренажёров.** Прогресс «Глаголы», «Существительные», «Предлоги и
   прилагательные» и навыки активного тренажёра карточек зеркалируются в таблицу
   `user_progress_state` (один JSON-документ на пользователя и коллекцию). Слияние по записям:
   побеждает более поздний ответ, сброс несёт метку времени и не откатывается старой копией.
2. **Очередь повторной отправки карточек.** Оценка, изменение и удаление карточки сначала
   записываются в очередь (localStorage) и вычёркиваются только после подтверждения сервера.
3. **Колода в IndexedDB.** Вместо одной JSON-строки в localStorage; чтение синхронное из копии в
   памяти, старая колода переносится при первом запуске.
4. **Лимит новых слов в день** (10 / 20 / 40 / без лимита, по умолчанию 20) для обычной тренировки
   карточек. Пачка из словаря, «Пройти заново» и фильтр «Новые» не ограничены.
5. **Расписание FSRS для существительных и других частей речи.** «Тренировать» при фильтре «Все»
   берёт только слова, которым пришёл срок, по 20 за раз.
6. **Экран «Сегодня» на главной.** Строка на тренажёр: сколько повторений и сколько нового.
7. **Общий признак «трудное слово».** Слово, которое не даётся в грамматическом тренажёре,
   попадает в «Сложные» карточек.
8. **Потоковый ответ в «Обсудить с AI».** Маршрут отдаёт NDJSON-события `partial` / `done`.
9. **Ленивая загрузка экранов** через `next/dynamic` с фоновой предзагрузкой.
10. **Разгрузка больших компонентов.** `CardsView` 3120 → ~2380 строк, `DiscoverView` 2570 → ~1900
    (стили и части списков вынесены, логика не менялась).

## Требуется от владельца

Применить миграцию `supabase/migrations/20261111120000_user_progress_state.sql` (SQL Editor в

раньше: прогресс тренажёров остаётся на устройстве и ждёт в очереди на отправку.

## Риски и продолжение

- Синхронизация прогресса между двумя устройствами вживую не проверена: таблицы ещё нет.
- Показ потока в окне чата проверен только на уровне сервера и типов, не глазами.
- Слова, выученные в «Существительных» до расписания, считаются «к повторению» и получат интервал
  при следующем ответе; первые дни счётчик там будет большим.
- CSS по разделам не разделён: 80% объёма — общие `globals.css` и `modal.css`, выигрыш был бы мал.
- `CardsView` всё ещё держит всё состояние тренировки в одном компоненте; следующий шаг — вынести
  сессию тренировки в отдельный хук.
- URL для экранов и ограничение частоты запросов к AI-маршрутам не делались.
