## Сделано

Добавлена возможность зацикливать фрагмент аудиокниги в режиме «Читать текст синхронно» —
метод «слушай, пока не начнёшь различать слова на слух» (аналог матричного метода
Н. Замяткина), плюс общий переключатель видимости текста.

- Кнопка повтора на каждом предложении зацикливает его **и** столько следующих предложений,
  сколько нужно, чтобы набрать ~30 секунд. Транскрипция режет текст по знакам препинания,
  так что одно «предложение» может длиться от 2 до 80 секунд — зацикливать ровно одно
  предложение не подходит под метод, нужен блок стабильной длины.
- Свежий цикл всегда стартует с скрытым текстом («Слушайте — текст скрыт, пока не начнёте
  различать слова»); кнопка «Показать текст» раскрывает весь зацикленный блок целиком
  (общий ключ на группу предложений, а не на каждое по отдельности).
- Независимо от цикла у активного (сейчас читаемого) предложения есть отдельная
  кнопка-глазик — скрыть/показать текст вручную, без включения повтора.
- Кнопка «Показать весь текст» наверху полностью отключает и размытие, и скрытие —
  возвращает обычный режим (весь текст виден, караоке работает как раньше).
- По умолчанию предложения, которые аудио ещё не достигло, размыты (`filter: blur`),
  чтобы не читать вперёд плеера.

## Риски и продолжение

- **Не связанные с этой веткой находки, зафиксированные, но не исправленные:**
  - Повторное открытие ранее транскрибированной главы иногда снова уходит в платный
    вызов Gemini вместо попадания в серверный кэш Supabase (`audiobook_transcripts`) —
    таблица и кэш-логика существуют и работают в части случаев (проверено прямым SQL:
    кэш для `kafka_galerie_librivox` и `alices_abenteuer_0911` реально есть и мгновенно
    отдаётся при повторном открытии той же главы), но при другой последовательности
    действий владелец проекта получил `Failed to fetch` на длинной (17 мин) главе —
    похоже на рассинхрон `chapterIndex` между клиентом и кэшем либо сетевую проблему
    при скачивании длинного файла с archive.org. Требует отдельного воспроизведения
    и разбора — не диагностировано до конца.
  - `npm run lint`/`npm test` репозитория целиком не проходят из-за существующего долга
    в несвязанных файлах — стоит учитывать при интеграции нескольких веток.
- Для реального использования репит-фичи нужен настроенный `GEMINI_API_KEY` — без него
  read-along вообще не показывает предложений (существующее ограничение, не новое).
