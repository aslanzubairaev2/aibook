# Handoff: network-first видео и AI-поиск

- Агент: Codex
- Ветка: `feature/video-learning-hub`
- Commit: `9dfe5dc`
- Статус: ready-for-review

## Сделано

- Каталог видео теперь сначала ищет актуальные результаты YouTube; старые локальные подборки
  используются только как резерв при ошибке сети или пустой выдаче.
- Добавлены AI-интерпретация запроса Gemini, постраничная выдача, быстрые темы и фильтры по
  языку, CEFR, категории, длительности и подтверждённому синхронному тексту.
- Перед значком «Синхронный текст доступен» сервер проверяет доступность транскрипта; результаты
  и их метаданные кэшируются на пять минут.
- Перекрывающиеся таймкоды автосубтитров YouTube нормализуются до начала следующей фразы:
  это устраняет отставание активной строки на одну-две реплики.
- Поиск из контекста слова или книги также проходит через сетевой поиск. Ошибки YouTube показывают
  понятное состояние и резервную выдачу.
- Исправлен общий `WordModal` в видеоплеере: ему передавались неверные имена props, что вызывало
  `lang.trim()` у `undefined`. Проверена общая модалка: читалка и остальные места используют тот
  же компонент с корректными props.
- Для локальной разработки добавлен строго dev-only допуск к серверному Gemini/TTS при
  `AI_ALLOW_DEV_AI=true` и наличии `GEMINI_API_KEY`; ключ в клиент не передаётся.

## Риски и продолжение

- YouTube не даёт стабильного публичного API: HTML-парсинг и проверка транскриптов могут быть
  медленнее официального API и иногда возвращать резервную подборку. Для production-надёжности
  следующий шаг — подключить YouTube Data API с квотой и continuation-токенами.
- Полноценная очередная страница сейчас берётся из доступного набора первого ответа YouTube;
  последующие страницы ограничены тем, что возвращает этот ответ.
- `next-env.d.ts` и `public/sw.js` обновлены production-сборкой и включены в commit.
