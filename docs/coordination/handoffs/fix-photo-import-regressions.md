## Сделано

- Ошибка со скриншота воспроизведена новым интеграционным тестом на исходном
  `dictionaryStore.ts` из HEAD до исправления: HTTP 500 и
  `column dictionary_entries.content_type does not exist`.
- Исправлены чтение и запись слов на базе без `content_type`, включая отставший
  кеш схемы PostgREST. Повторяется только запрос с кодом отсутствующей колонки;
  ошибки доступа не скрываются.
- Добавлена совместимость MCP search/list_batch_words; фильтры владельца
  сохраняются при повторном запросе.
- Фразы и выражения не сохраняются под ложным типом word: для них возвращается
  понятное требование применить миграцию.
- 16 интеграционных тестов проверяют настоящие серверные обработчики и SDK через
  локальные HTTP-имитации Supabase/Gemini: словарь/пачки/карточки, повторное фото,
  прогресс, ошибки, авторизацию, лимит изображения, фото текста и домашнего задания.
- `npm test` автоматически находит тесты, включая ранее пропущенные файлы.
- UTC зафиксирован только в тестовом процессе, устранив два старых падения
  календарных тестов на Windows с местным часовым поясом.
- `prebuild` запускает полный `npm test`, блокируя сборку при падении тестов.
- CI запускает lint/test/build независимо в рабочих ветках и PR.
- Добавлена `npm run check:schema`: проверка наличия колонок SELECT limit(0),
  без загрузки пользовательских записей и без изменения базы.
- Lint ограничен исходниками web-приложения; служебные каталоги исключены.

## Риски и продолжение

- В production применены и записаны в `supabase_migrations.schema_migrations`
  версии `20260817120000`, `20260818120000`, `20260914000000`; Data API видит
  новые колонки. До миграции было 594 карточки типа word и 1 типа sentence,
  поэтому нормализация не меняла неподдерживаемые значения.
- Чистая ветка создана от актуального `origin/main`; два посторонних локальных
  коммита из первой опубликованной ветки сюда не входят.
- Branch protection и обязательность GitHub checks не менялись. Прямой вызов
  `next build` обходит npm prebuild; команда выпуска должна быть `npm run build`.
- check:schema не проверяет SQL constraints/RLS и автоматически не мигрирует базу.
- При сбое карточек существующий маршрут убирает пачку, но уже записанные слова
  могут остаться без неё (FK ON DELETE SET NULL). Атомарная транзакция всех трёх
  таблиц в эту задачу не добавлялась.
- Чужие изменения в VerbsQuiz, activeTraining, next-env, public/sw/workbox,
  android-app и миграции last_view не включались в commit. Побочные изменения
  public и next-env от сборки восстановлены из побайтовой копии состояния до сборки.
